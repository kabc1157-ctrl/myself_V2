## 현재 증거

## 2026-11-19 홈 시간표 색상 1단계

홈 원형 시간표의 `layoutLabel()` 기반 일정명 배치 로직은 이미 유지되고 있음을 확인했다. 우선순위·Google·TODO/브레인 덤프의 공통 색상 토큰을 각각 `#FFE3B3`, `#8EBBF0`, `#DCCCF4`로 통일하고, 홈 현재·다음 일정 카드와 시간순 일정 표시에도 같은 색상 규칙을 적용했다. `npm run typecheck`는 통과했으며 실제 브라우저 검증은 미실행이다. 일정 관리 표형 시간표 구현은 다음 단계로 남아 있다.

## 2026-11-19 일정 관리 표형 시간표 2단계

`/schedule`에서만 전용 `ScheduleGridTimeTable`을 사용하도록 분리하고, 4열·6행의 24시간 표와 기존 TODO/계획 저장·수정·배치 해제 액션을 연결했다. 분 단위 위치, 수면 설정, 우선순위 색상 우선 적용, Google/TODO 색상을 반영했다. 홈 원형 시간표와 `clock-labels.js`는 변경하지 않았다. `npm run typecheck`는 통과했으며 실제 브라우저·lint·Vitest·build 검증은 미실행이다.

## 2026-11-19 표형 시간표 안정화

마이페이지 시간 문자열을 직접 파싱하도록 보완해 표형 시간표의 숙면 구간 계산을 복구했고, 시간 칸별 반복 테두리를 제거해 연속 일정이 끊겨 보이는 현상을 완화했다. `npm run typecheck`는 통과했으며 실제 브라우저·lint·Vitest·build 검증은 미실행이다.

- Supabase V2 로그에서 `42501` 확인.
- 원인: TODO 트리거가 호출하는 `recalculate_project_status()` 및 `recalculate_one_project(uuid)` 실행 권한 부족.
- V2 원격 프로젝트에 최소 권한 SQL 적용 완료.
- 실제 사용자 계정 저장 성공 여부는 아직 미검증.

## 상태 규칙

코드만 존재하면 `부분 구현`, 코드 검사만 통과하면 `검증 대기`, 실제 로그인 브라우저에서 저장·조회·수정을 확인해야 `완료`로 변경한다.

## 2026-11-19 투자 종목 관리 구조

투자 페이지에 종목 추가와 종목 리스트를 분리하고, 보유 종목은 거래 기반 보유 수량이 양수인 항목만 표시하도록 유지했다. 종목 코드 선택 입력을 지원하기 위한 V2 마이그레이션을 추가했으며, 매매일지가 연결된 종목은 연쇄 삭제를 막기 위해 삭제를 거부한다. 브라우저·원격 마이그레이션 적용 검증은 대기 중이다.

## 2026-11-19 프로젝트 상단 UI

프로젝트 상단 헤더에 일정 관리 이동 버튼을 추가하고 기존 일정표·프로젝트 탭을 제거했다. 프로젝트 추가 폼에 설명·일정·카테고리·상태 입력을 추가했으며, 프로젝트 회고 독립 접이식 블록을 추가했다. 브라우저 검증은 미실행이다.

## 2026-11-19 프로젝트 목록·TODO UI

상태별 프로젝트 그룹 접기·펼치기, 프로젝트 내부 TODO 추가·수정·삭제 아이콘, 프로젝트 선택·날짜 입력을 반영했다. 기존 프로젝트·TODO·회고 저장 액션과 RLS를 재사용했으며 브라우저 검증은 미실행이다.

## 2026-11-19 일정 관리 하단 UI

`/schedule`의 원형 시간표는 기존 `TimeTable`을 그대로 사용하며, 일정관리 화면에서만 종일 일정 목록·시간순 목록·수면 안내·타이머 요약 UI를 숨겼다. TODO 시간 배치 입력과 원형 그래프의 일정·수면·현재 시각 계산은 유지한다. 범례는 시간표 상단 우측으로 이동하는 스타일을 적용했다. 브라우저 검증은 미실행이며, typecheck는 통과했다.

## 2026-11-19 일정 관리 단일 블록 시간표

`/schedule` 표형 시간표를 오전·오후·저녁 3열 × 8행으로 변경하고, 일정별 overlay 블록을 열 단위로만 분할해 렌더링한다. 한 일정은 같은 열에서 하나의 연속 DOM 블록으로 표시하며, 열 경계를 넘을 때만 표시 조각을 나눈다. 숙면은 일정 관리 표에서 제외하고 홈 원형 시간표에는 영향을 주지 않는다. `npm run typecheck`와 관련 Vitest 6개가 통과했다. 실제 브라우저 모바일·PC 검증은 미실행이다.

## 2026-11-20 성향 검사 P2 — 35문항 채점 엔진

- 사용자 승인된 35문항 수는 유지하면서 문항 분포를 **Big Five 20 / 동기 6 / 실행 9**로 조정함. 10개 영역 모두 최소 3문항(영역별 4/3/3개).
- 질문 35개와 역채점 후보를 `src/core/personality/questions.ts`에 버전 `ieumsae-35-provisional-v2`로 고정. 기존 V2 원격 DB의 평가 응답이 0건임을 확인하고 변경.
- 채점 엔진: `src/core/personality/scoring.ts`. 5점 척도 1~5를 정방향 그대로, 역방향은 `6 - 응답`으로 변환한 후 영역 평균을 `Math.round((평균 - 1) * 25)`로 0~100점 환산.
- 내부 설명 구간: 0~39 낮음, 40~69 혼합, 70~100 높음. 백분위/비교/임상진단이 아닌 임시 해석 규칙.
- 모든 35개 문항이 올바르게 입력되어야 점수 계산 가능. 누락, 추가 ID, 문자열 외 응답, 1~5 범위 초과는 오류 처리. 초안 저장은 정상적인 부분 응답만 수용.
- 향상초점과 예방초점은 독립적으로 계산. 상반된 응답 탐색을 위해 영역별 응답 분산폭도 함께 반환.
- Vitest 단위 테스트 10종 이상 작성(중립값, 양극단, 역채점, 평균 반올림, 독립성, 구간 경계, 불완전/조작 입력, 초안, 원본 불변).
- 정적 소스 검사에서 질문 35개, 영역 10개, 영역별 최소 3개, 역채점 15개 및 채점식과 테스트 파일 존재 확인.
- GitHub 연결 파일만 직접 수정 가능했고 테스트 실행 컨테이너에서 GitHub DNS 접속이 불가해 lint/typecheck/Vitest/build는 **미실행**, 로그인 브라우저 검증 역시 미실행.
- 점수 계산 함수를 프로덕션 제출/DB 저장/결과 UI에 아직 연결하지 않음. P3 리포트 규칙 및 최종 제출 트랜잭션이 완성되기 전 결과를 확정·공개하지 않음.
- 본 검사는 자체 제작 예비 자기보고 문항이며 검증된 Mini-IPIP 또는 RFQ 원검사라고 표현하지 않음.
